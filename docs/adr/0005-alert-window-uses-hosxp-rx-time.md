# Alert Window ตัดสินด้วย Rx Time (เวลาสั่งยาใน HOSxP) ไม่ใช่เวลาเข้าคิว

ADR-0004 ให้ auto-send เฉพาะแถวที่ "เกิด" ในช่วงเวลา โดยใช้ `created_at` (เวลาที่ worker เขียนแถว
ลง `had_queue`) เป็นตัวแทนเวลาที่เกิด — ตรวจของจริงแล้วพบว่า `created_at` ช้ากว่า
`opitemrece.rxtime` ของ HOSxP ราว 5-7 นาทีในวันปกติ และช้าเป็นชั่วโมงเมื่อ worker หรือ MySQL
หยุด (เกิดจริง 2026-09-25 MySQL ล่ม 15:2x-20:09 ยาที่จ่ายช่วงนั้นเข้าคิวทีเดียวตอน ~20:10) ถ้าตั้ง
16:30-08:00 ยาที่จ่าย 15:30 (นอกช่วง) จะถูกนับว่าเกิด 20:10 (ในช่วง) แล้วถูกส่งอัตโนมัติ ผิดจาก
ความตั้งใจของห้องยา เราจึงเก็บ **Rx Time** = `rxdate` + `rxtime` จาก HOSxP ไว้ในคอลัมน์ใหม่
`had_queue.rx_at` แล้วให้ worker กรองด้วย `COALESCE(rx_at, created_at)` (grill session 2026-09-25)

## Considered Options

- **Rx Time จาก HOSxP ใช้ `created_at` แทนเมื่อไม่มีค่า (เลือก)** — ตรงกับเวลาจ่ายยาจริงไม่ว่า
  worker จะดึงช้าแค่ไหน แถวเก่าที่ยังไม่มี rx_at พฤติกรรมเหมือนเดิมทุกประการ
- คงใช้ `created_at` — ง่ายกว่า แต่เพี้ยนตามความต่อเนื่องของ worker/ฐานข้อมูล ซึ่งเครื่องจริงหยุดได้
- `vsttime` (เวลาเปิด visit) — เป็นเวลาที่คนไข้มาถึง ไม่ใช่เวลาสั่งยา (ต่างกันเป็นชั่วโมงในข้อมูลจริง)

## Consequences

- **ยาเดิมจ่ายหลายครั้งในวันเดียวถูกรวมเป็นแถวเดียว** (unique `hn+icode+vstdate`) → เก็บ
  **เวลาล่าสุด** ด้วย `GREATEST(COALESCE(rx_at, VALUES(rx_at)), COALESCE(VALUES(rx_at), rx_at))`
  (ไม่ขึ้นกับลำดับแถวจาก HOSxP และ NULL ไม่ทับค่าเดิม) — แถวรอส่งที่จ่ายรอบแรกนอกช่วงแล้วมีการ
  จ่ายซ้ำในช่วง จะกลายเป็นส่งอัตโนมัติได้ ส่วนแถวที่ส่งไปแล้วจะไม่ส่งซ้ำ (ข้อจำกัดเดิม)
- **Rx Time อยู่ในช่วงแต่เข้าคิวหลังหน้าต่างปิด** (เช่นสั่ง 07:58 ดึงได้ 08:00 หรือดึงช้าเพราะระบบล่ม
  ช่วงกลางคืน) → ส่งตอนหน้าต่างเปิดรอบถัดไป ช้าแต่ไม่หาย ตามหลัก fail-open "พลาดไปทางแจ้งเกิน"
- **เทียบเฉพาะเวลาของวัน ไม่สนวันที่** เหมือน ADR-0004 — แถวเก่าที่ Sync ย้อนหลังและ Rx Time ตกในช่วง
  จะถูกส่งอัตโนมัติรอบถัดไปที่หน้าต่างเปิด (ปลอดภัยกว่าเดิม: ใช้ `created_at` การกด Sync ตอน 17:00
  จะทำให้ทุกแถวที่เพิ่งเข้าคิวนับเป็น 17:00 และถูกส่งทั้งหมด)
- **มีผลย้อนหลังครั้งแรกที่ deploy** — ingest ดึงย้อน 7 วันทุกรอบ จึงเติม rx_at ให้แถวในช่วงนั้นทันที
  แถวรอส่งที่ `created_at` นอกช่วงแต่ Rx Time ในช่วงจะกลายเป็นส่งอัตโนมัติได้ (ตอนออกแบบ เครื่อง
  รพ.เชียงกลางมีแถวรอส่ง 3 แถว สั่งยากลางวันทั้งหมด จึงไม่มีผล)
- **เพิ่มคอลัมน์ผ่าน `db_migrate.php` เท่านั้น** (`ensure_missing_columns()` — ครั้งแรกของโปรเจกต์ที่
  เติมคอลัมน์ให้ตารางที่มีอยู่แล้ว) เช็ค `information_schema` แทน `ADD COLUMN IF NOT EXISTS` เพราะ
  MySQL 8 ไม่รองรับ · ถูกเรียกทั้งจาก CLI, ปุ่ม Setup MedAlert_DB และ `task/update.ps1` หลังอัปเดต
- **worker ตรวจคอลัมน์อย่างเดียว ไม่แก้ schema เอง** — ถ้า migrate ไม่ผ่านที่ รพ. ไหน (ไม่มีสิทธิ์
  ALTER, update ข้ามขั้น migrate) `HAD.php` และปุ่ม Sync จะทำงานแบบเดิมด้วย `created_at` และ log
  `✗ ไม่มีคอลัมน์ had_queue.rx_at` ทุกรอบ แทนที่จะ error จน HAD เงียบทั้ง รพ.
- **HOSxP บางเครื่องอาจดึง `rxdate`/`rxtime` ไม่ได้** (V3 บางเวอร์ชัน/สิทธิ์ระดับคอลัมน์) — source
  query ถอยกลับไปใช้ query เดิม แถวไม่มี rx_at ใช้ `created_at` แทน และ log คำเตือน
- `had_rx_at()` validate เข้ม เพราะค่าเพี้ยนที่หลุดไป MySQL จะเป็น `0000-00-00 00:00:00` ซึ่ง
  TIME = 00:00 ตกในช่วงข้ามเที่ยงคืนแล้วถูกส่งผิดๆ · ตัดทศนิยมวินาทีของ PostgreSQL ทิ้ง
- หน้า `had_queue_ui.php` แสดงวันที่+เวลาที่ worker ใช้ตัดสินจริง และไฮไลต์แถวรอส่งเมื่อเปิดช่วง
  (เขียว = ส่งอัตโนมัติ, ส้ม = นอกช่วงต้องกดส่งเอง, เทา = ไม่มีเวลาสั่งยาใช้เวลาเข้าคิวแทน)
- ส่วนที่คงเดิมจาก ADR-0004: per-row eligibility, กรองที่ SQL `WHERE` กัน starvation, ตัด Re-queue,
  "ส่งซ้ำทันที" ไม่ถูกจำกัด, gate "ตอนนี้อยู่ในช่วงไหม" ของทั้ง worker, fail-open เมื่อปิด/`start == end`
