# บังคับ Alert Window ที่ Worker ไม่ใช่ที่ Cron

ห้องยาต้องการให้ HAD Alert ยิง LINE เฉพาะช่วงเวลาที่กำหนดต่อวัน (เช่น 16:30-08:00 ซึ่งข้ามเที่ยงคืน) แทนที่จะแจ้งทันทีทุกครั้งที่เจอ record ใหม่ตลอด 24 ชม. เหมือนโมดูลอื่น ทางที่ตรงที่สุดคือแคบ trigger ของ Cron เอง — ไฟล์ `task/HAD_Auto Sender.xml` ที่ติดตั้งเข้า Windows Task Scheduler (ใส่ `<Duration>` ให้ `<Repetition>`) — แต่การสร้าง/แก้ scheduled task ต้องใช้สิทธิ์ Administrator (`task/install_tasks.bat` ถึงต้อง self-elevate ผ่าน UAC) ซึ่งหน้าเว็บที่รันใต้ Apache สั่งเองไม่ได้ และ รพ. ที่ deploy ไปแล้วแต่ละแห่งก็ไม่มีใครเข้าไปแก้ให้ได้

เราจึงให้ **Worker กั้นตัวเอง**: `task/HAD_Auto Sender.xml` ไม่ถูกแตะเลย (ยังเป็น `Repetition PT5M` ไม่มี `<Duration>` วิ่ง 24 ชม. เหมือนเดิม) แต่ `HAD.php` อ่าน Alert Window จาก `secrets/alert_windows.json` ผ่าน `alert_window_loader.php` แล้ว**ข้ามเฉพาะขั้น Send** เมื่ออยู่นอกช่วง ส่วน Ingest ยังวิ่งทุกรอบ เจ้าหน้าที่ตั้งค่าเองได้จากปุ่ม "ช่วงเวลาแจ้งเตือน" ในหน้า `had_queue_ui.php` โดยไม่ต้องมีสิทธิ์ผู้ดูแลระบบบนเครื่องใดเลย

## Considered Options

- **Worker กั้นตัวเอง อ่านจาก JSON (เลือก)** — ตั้งค่าผ่านหน้าเว็บได้ทุก รพ. โดยไม่ต้องใช้สิทธิ์ admin, มีผลทันทีในรอบถัดไป, log บอกเหตุผลที่ไม่ส่งไว้ใน `logs/had_task_run.log`, และแยก Ingest กับ Send ออกจากกันได้ ซึ่ง Cron ทำไม่ได้เพราะมันเห็นแค่ "รัน .bat หรือไม่รัน"
- แคบ `<Duration>` ในไฟล์ XML ของ Cron — **ปฏิเสธ**: ต้อง Administrator/UAC หน้าเว็บสั่งไม่ได้ ต้องส่งคนไปนั่งแก้ทีละ รพ. และมันจะหยุด **Ingest** ไปด้วย ทำให้หน้า Queue UI/Dashboard ไม่เห็นคนไข้ของวันนี้เลยจนกว่าจะถึงเวลา
- กั้นในฐานข้อมูล (เพิ่มเงื่อนไขเวลาใน `WHERE` ของ `had_send_pending()`) — **ปฏิเสธ**: ซ่อนนโยบายไว้ใน SQL ทำให้ log ไม่บอกว่าทำไมไม่ส่ง และผูกกับ dialect โดยไม่จำเป็น
- เก็บช่วงเวลาไว้ใน `secrets/module_filters.json` — **ปฏิเสธ**: CONTEXT.md นิยาม Condition ว่าเป็น "เกณฑ์คัดกรองผู้ป่วยในขั้น Ingest" ส่วนหน้าต่างเวลาเป็นนโยบายของขั้น Send คนละขั้นกัน ถ้าเอามารวมต้องใส่ special case ชนิดฟิลด์ใหม่ใน schema ของ filter modal และทำให้คำว่า Condition กำกวม

## Consequences

- **คิวจะยาวขึ้นระหว่างวันโดยตั้งใจ** — Ingest วิ่งทั้งวัน แถวจึงค้างเป็น Pending ใน `had_queue` แล้วไหลออกทีเดียวตอนหน้าต่างเปิด หน้า `had_queue_ui.php` มีแถบอธิบายสถานะไว้แล้ว แต่ **Dashboard กับรายงานรายวันไม่รู้จัก Alert Window** จะเห็นยอด "รอส่ง" ไต่ขึ้นทุกวันแล้วรีเซ็ตทุกคืน — เป็นเรื่องที่มีโอกาสถูกแจ้งว่า "ระบบค้าง" มากที่สุด
- **ความจุมีเพดานจริง** — ส่งได้ = (ความยาวหน้าต่าง ÷ รอบ Cron 5 นาที) × `LIMIT 50` ต่อรอบ เช่น 16:30-08:00 (15.5 ชม.) ≈ 186 รอบ ≈ 9,300 รายการ/วัน โมดัลคำนวณตัวเลขนี้สดให้เห็นตอนเลือกเวลา **กับดักคือถ้าตั้งหน้าต่างสั้นเกินไปจนคิวล้น จะไม่มี error ให้เห็นเลย** เพราะแถวส่วนเกินไม่เคยถูก `SELECT` ออกมา ช่อง `attempt` จึงไม่ขยับ ต่างจากเคส "ส่งไม่ผ่าน" ตามปกติ — จึงเตือนสีส้มเมื่อหน้าต่างสั้นกว่า 30 นาที และสีแดงเมื่อสั้นกว่ารอบ Cron
- **เวลาเริ่มส่งจริงช้ากว่าที่ตั้งได้ถึง 5 นาที** และหน้าต่างที่สั้นกว่ารอบ Cron อาจไม่มี tick ตกอยู่ในช่วงนั้นเลย = ไม่ส่งอะไรทั้งวัน
- **fail-open ทุกทาง** — ไฟล์หาย / JSON เสีย / ค่าผิดรูปแบบ / `start == end` ทั้งหมดแปลว่า "ส่ง 24 ชม." ไม่ใช่ "เงียบ" ระบบแจ้งเตือนทางการแพทย์ควรพลาดไปทาง "แจ้งเกิน" ไม่ใช่ "ไม่แจ้ง" ด้วยเหตุผลเดียวกัน `enabled` จึง default เป็น `false` — รพ. ที่อัปเดตโค้ดมาแล้วพฤติกรรมไม่เปลี่ยนจนกว่าจะเปิดเอง และ**ไม่มีวิธีสั่ง "ห้ามส่งอัตโนมัติเลย" ผ่านหน้าต่างเวลา** (ถ้าต้องการจริงคือปิดสวิตช์แล้วปิด scheduled task)
- **การแจ้งเตือนถูกเลื่อนจริง** — ยา HAD ที่จ่ายตอน 09:00 จะถูกแจ้งตอน 16:30 (ช้า 7.5 ชม.) เป็นการแลกที่ห้องยาต้องรับทราบและเป็นเจ้าของการตัดสินใจ ไม่ใช่รายละเอียดทางเทคนิค และเพราะ `ORDER BY id ASC` คงไว้ตามเดิม เคสที่ใหม่ที่สุดจะถูกส่ง**ท้ายสุด**ของรอบระบาย
- **ปุ่ม "ส่งซ้ำทันที" ไม่ถูกจำกัดเด็ดขาด** — เป็นทางออกเมื่อมีเคสด่วนนอกเวลา แต่กล่องยืนยันจะเตือนเพิ่มว่าขณะนี้อยู่นอกช่วง โดยคำนวณจากนาฬิกาเบราว์เซอร์ตอนคลิก ไม่ใช่ค่าที่ PHP คำนวณไว้ตอน render (หน้านี้มักถูกเปิดค้างข้ามเวลา 16:30 พอดี)
- **นาฬิกาเครื่องเซิร์ฟเวอร์กลายเป็นของสำคัญแบบเงียบ ๆ** — ถ้าเวลาเพี้ยน หน้าต่างจะทำงานผิดเวลาโดยไม่มีอะไรฟ้อง จึงแสดงเวลาเครื่องไว้บนหน้า Queue UI เป็นตัวช่วยวินิจฉัยที่ถูกที่สุด
- **`secrets/alert_windows.json` ต้องอยู่ใน `.gitignore` ทั้งบรรทัด ignore และบรรทัด `!…example.json`** — `.gitignore` ของโปรเจกต์นี้ระบุไฟล์ secrets ทีละชื่อ ไม่ใช้ wildcard ถ้าลืม ไฟล์จะกลายเป็น tracked แล้วเส้นทางอัปเดตแบบ git (`git reset --hard origin/master` ใน `task/update.ps1`) จะทับค่าที่ รพ. ตั้งไว้ทุกครั้งที่อัปเดต ขณะที่เส้นทาง ZIP (`robocopy /XD secrets`) รอด — กลายเป็นบั๊กที่เกิดเฉพาะบาง รพ.
- เขียนไฟล์แบบ `.tmp` + `rename()` (atomic บน NTFS) เพราะ worker อ่านไฟล์นี้ทุก 5 นาที อาจชนจังหวะบันทึกจากหน้าเว็บพอดี — ต่างจาก `module_filter_action.php` ที่ใช้ `file_put_contents` ตรง ๆ โดยตั้งใจ
- ดูคำว่า "Alert Window" ใน CONTEXT.md · โครงไฟล์เป็น module-keyed เหมือน `module_filters.json`/`flex_themes.json` จึงขยายไปโมดูลอื่นได้โดยไม่ต้องแก้ loader
